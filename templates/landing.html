How the AI works

Tested in a twin before it reaches the floor.

A trained agent plus a planner that tries every move first. Nothing reaches you unless it cuts predicted waiting time.

STEP 1

Digital twin

A simulator of the warehouse floor: 4 zones, 10 robots, one tick per second, orders arriving at random. A robot handles 2 orders a minute and needs 40 s to drive to another zone.

STEP 2

Baseline rules

Each robot stays in its home zone and takes the next order there. This is what the agent has to beat.

STEP 3

RL agent

Every 10 s the PPO agent reads queue, robots, last-minute demand and web signal for each zone, then moves one robot or waits. Every zone always keeps at least one robot.

STEP 4

Training

1.5 million decisions on random days with surprise spikes, robot failures and rush hours. We keep the checkpoint that does best on held-out days.

STEP 5

Live advice

The fleet page copies today's floor into the twin, tries every possible robot move, plays the next 15 minutes for each and keeps the best one to three.

STEP 6

Runs anywhere

The trained network runs with numpy only, so the web app deploys without PyTorch.

The honest part. The agent clearly beats the basic rules on every standard scenario and roughly matches a hand-tuned heuristic. It struggles when the busy zones are shuffled, because it never saw that during training.

That is why live advice uses the digital-twin planner, which tests every move and never suggests one that makes things worse. Next step: train longer with random busy zones.

Run it

Up and running in five minutes.

Demo data loads on the first run. Chart.js and the fonts are bundled, so it works offline.

On your laptop

$ python -m venv venv
$ venv\Scripts\activate   # Mac/Linux: source venv/bin/activate
$ pip install -r requirements.txt
$ python app.py
# open http://127.0.0.1:5000

To use live demand signals, set TINYFISH_API_KEY before starting, or paste the key in Settings as admin. Without a key the app keeps working with saved and manual signals.
